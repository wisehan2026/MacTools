# MacTools

仅在本机使用的 Swift 原生 macOS 工具。SwiftUI + AppKit，最低 macOS 15；本项目已在当前 Apple Silicon Mac、Xcode 27 / Swift 6.4 环境构建。

## 构建与运行

打开 `MacTools.xcodeproj`，选择 `MacTools` scheme 后运行。也可执行：

```sh
bash scripts/build.sh
open build/Build/Products/Release/MacTools.app
```

按当前使用约定，直接运行项目内的 `build/Build/Products/Release/MacTools.app`，不再复制到其他目录。工程默认本地 ad-hoc 签名，不需要付费开发者账号。

ad-hoc 签名的应用身份包含二进制哈希，重新构建后旧的屏幕录制授权可能不再匹配，即使系统设置里的开关仍显示开启。本次已从系统日志确认过 `Failed to match existing code requirement`。遇到同样问题时，退出 MacTools，在系统设置中移除旧的 MacTools 屏幕录制条目，再添加**当前项目 Release 路径**的应用并允许，随后重新运行。仅关闭、再开启旧条目可能仍保留旧签名。如果以后配置稳定的开发签名，可减少这种重新授权的情况。

应用常驻菜单栏。启用剪贴板历史时，关闭窗口仍继续记录；通过菜单栏「退出 MacTools」完全退出。开机启动在设置中开启。

## 功能开关与外观

「设置 → 功能开关」提供剪贴板历史、截图、滚动长截图、表情包、录屏、文件搜索、文字识别、常用短语和空间管理的独立开关，默认全部启用。关闭后立即从主页、菜单栏和快捷键列表移除，对应的全局快捷键、应用内快捷键及直接窗口入口均禁用；已打开的功能窗口也会关闭。剪贴板、表情包对应的设置分类随开关隐藏。

总入口与设置始终保留，可以随时重新启用工具。关闭不会清空已保存的数据或原快捷键，再次开启会恢复；已有数据仍遵循原本的保留规则。本地表情图库继续永久保留。截图、OCR、长截图或录屏正在采集、准备或收尾时，需先完成或取消当前任务再关闭该功能；已经生成的截图编辑和录像预览保留，便于保存未完成的草稿。

关闭剪贴板历史会停止自动记录；其他功能仍可正常复制到系统剪贴板，但不新增历史。重新启用仅记录之后的新复制，不补录关闭期间的内容。关闭文件搜索停止后台查询，关闭表情包搜索停止当前搜索与预下载，保留磁盘缓存及本地图库。

「设置 → 通用 → 应用外观」支持「跟随系统 / 浅色 / 深色」，默认跟随系统。切换立即作用于应用的 SwiftUI 内容、原生窗口及弹窗，并在重启后保留；跟随系统会解除应用的强制外观，自动响应 macOS 深浅色切换，不修改系统外观设置。

## 快捷键

截图、长截图、录屏和 OCR 的快捷键直接进入采集流程，默认选择区域，截图、录屏与 OCR 会记住上次使用的模式和尺寸。状态栏菜单右侧显示当前已配置的快捷键，点击功能与按快捷键相同，直接执行。仅从 App 主页点击功能时打开二级参数窗口。剪贴板、搜索等快捷键打开对应功能窗口，系统复制粘贴保持不变。

| 功能 | 默认快捷键 |
| --- | --- |
| 总入口 | Control + Option + 空格 |
| 剪贴板历史 | Control + Option + V |
| 截图 | Control + Option + S |
| 滚动长截图 | Control + Option + L |
| 开始录屏 / 显示录制控制条 | Control + Option + R |
| 文件搜索 | Control + Option + F |
| 表情包搜索 | Control + Option + M |
| 截图文字识别 | Control + Option + T |

设置中支持修改、恢复和停用。快捷键冲突会显示提示。系统 `⌘C`、`⌘V` 保持原有行为。在剪贴板历史中选择记录后复制，回到目标应用粘贴。

区域选择支持鼠标悬停建议：高亮鼠标下最前方的应用窗口范围，单击左键只截取当前建议范围；按住左键拖动则立即改为自定义区域，松开完成，Esc 取消。两种操作无需提前切换模式，单击时允许轻微抖动。指定像素尺寸时显示固定大小选框。跨屏窗口只选取当前显示器内可见部分，不跨显示器拼接。采集前自动收起 MacTools 的配置窗口、颜色面板和菜单，取消后恢复原窗口。

长截图期间再次按快捷键可结束并编辑。录屏期间再次按快捷键只显示控制条，点击「停止并编辑」完成录制。状态栏菜单的快捷键显示会随设置更新，停用后不再显示。截图和录像预览支持 `⌘W` 关闭，不自动保存；未保存的临时录像会删除，明确保存或导出的文件继续保留。

## 功能

- **剪贴板**：文字和图片，按自然日分组；默认今天及前两天，默认 1 GB。支持搜索、按类型筛选、收藏、去重、暂停、来源应用排除。收藏不自动清理；收藏或单条内容超出容量时跳过新增并提示。图片按日期目录保存，文字和索引保存在本地 JSON。
- **表情包搜索**：菜单栏「表情包搜索」或 `⌃⌥M` 打开窗口，输入中文/英文关键词后回车或点击搜索；支持静图、GIF 和类型筛选；缩略图固定每行 5 个。鼠标悬停在右侧播放大图，双击或点击复制后按 `⌘V` 粘贴。原始 GIF 数据完整保留，历史中独立归类为「表情包」，支持标题搜索、收藏、去重与重新复制。目标应用只支持静图时会读取 PNG 首帧。暂停自动记录时，主动复制表情包仍保存；容量或磁盘不足时仍尝试复制并明确提示未保存。
- **表情搜索来源**：在「设置 → 表情包」勾选单个或多个来源，也可点击「仅用此源」。提供 memecub、慕名表情、澄曜搜狗表情、ChineseBQB 和皮蛋表情包；默认保留原来的 memecub。拖动来源左侧手柄排序，或右键手柄上移、下移；结果按排序后的来源依次显示整组图片。跨源相同图片去重，优先保留靠前来源。仅调整顺序立即重排现有结果，不消耗查询，也不改变缓存分区。
- **表情搜索数量与缓存**：默认最多 50 条，按所选来源数向下均分：单源 50、双源各 25、三源各 16（48 条）、四源各 12（48 条）、五源各 10。开启「自定义每个来源的数量」后，每源可填 1～50 条，总量按设置相加，可超过默认 50 条；关闭自定义恢复均分。返回不足或有重复时按实际数量显示，不额外补齐。来源选择或分配数量变化后，按回车重新搜索。缓存按关键词、来源组合、分配数量及各来源分别保存结果、缩略图和原图。再次搜索各源优先联网，成功后替换该源本地记录；超限、断网或服务异常时只回退该源有效缓存，其余来源继续正常显示。
  默认保留 3 天（72 小时），在「设置 → 表情包」中调整为 1～365 天，也可手动清理。读取缓存不延长保留时间；应用启动、设置变更和运行期间每分钟清理过期索引与图片。图片下载失败时查看该图片会重试，未下载完成的图片无法保证离线使用。搜索缓存与剪贴板历史、收藏独立。
- **本地表情**：表情窗口顶部可切换「搜索 / 本地」。在本地页点击「添加表情」，选择静图或动图，自定义 1～100 字名称后保存；支持按名称搜索和静图/动图筛选。右键表情可修改名称、更换图片或删除，也可在大图预览下操作。原文件复制到应用私有目录，GIF 原始数据完整保留，移动导入原文件不影响使用。每行仍显示 5 张，悬停预览、双击复制并进入剪贴板历史的「表情包」分类。本地图库无需网络、不上传、不定期清除，搜索缓存清理和历史过期均不影响它；手动删除只删除图库副本。单张沿用 16 MB、2000 万像素和动图累计像素限制。
- **搜索结果一键添加本地**：在搜索结果的大图预览中点击「添加到本地」，或右键结果选择同名操作。直接保存原图与完整动图数据，不经过剪贴板；名称默认取结果标题（最多 100 字，空标题使用「表情包」），后续可在本地编辑。优先复用该结果的原图缓存，断网时已缓存的原图仍可添加。按原始内容去重，重复添加保留已有自定义名称；删除本地条目后可重新添加。切换分类时继续完成添加并刷新本地列表，关闭窗口或停用功能会取消尚未写入的任务。
- **截图**：区域、屏幕、窗口；自定义最终像素宽高和常用尺寸；箭头、文字、矩形、椭圆、画笔、马赛克；撤销、重做、缩放、悬浮置顶；复制、PNG 保存、复制并保存。
- **长截图**：框选正文区域后，手动向上或向下滚动鼠标或触控板，完成后点击「结束并编辑」。通过双向重叠匹配、原始像素细化和覆盖范围追踪拼接；向上新增内容插入顶部，向下新增内容放到底部，往返已有范围不重复拼接。每轮采样间隔 250 ms，跳过不可靠的帧，局部画面变化可容错。支持单显示器内纵向滚动，最多 50,000 px 高 / 1 亿像素。请慢速滚动，避免固定悬浮栏和动画；快速跳页、重复背景和动态聊天内容可能无法匹配。失败时回滚至上一段附近重试，或重新框选。
- **录屏**：区域、屏幕、窗口，MP4 / H.264，30 或 60 fps，倒计时；系统声音、麦克风分别开关，默认关闭。选区后显示红色范围边框和独立控制条，边框不拦截鼠标、不写入录像。停止后自动打开视频预览，录像此时位于系统临时目录；点击「保存原录像」或「导出新 MP4」才保留文件。关闭参数窗口不会停止录制，退出前需停止录制。
- **录像编辑**：播放与时间轴定位、按起止秒数裁剪；箭头、文字、矩形、动态马赛克，支持撤销/重做和每条标注的出现时间。标注坐标固定、不自动跟踪物体，时间按原录像计算。预览和导出共用逐帧处理器，标注实际写入新 MP4，保留音轨，不修改已存在的源文件。支持进度与取消，导出完成后可播放或定位文件。
- **文件搜索**：全局文件名搜索使用 Spotlight，指定目录直接扫描；类型筛选、隐藏文件开关、Quick Look 预览、打开、Finder 定位。全局结果受索引和文件访问权限影响；扫描不进入应用包，不跟随目录符号链接；结果上限 10,000 项。首版不搜索文件正文。
- **文字识别**：系统 Vision 中英文识别，本地运行，结果可编辑复制。
- **常用短语**：新增、编辑、保存、搜索与复制。
- **空间管理**：按剪贴板、截图、录像和缓存显示磁盘占用。清理历史保留收藏；导出文件手动移至废纸篓。只管理本软件记录的文件，不递归删除用户保存目录。

## 保存位置与权限

- 历史与媒体索引：`~/Library/Application Support/MacTools/`
- 永久本地表情：`~/Library/Application Support/MacTools/LocalMemes/`，`library.json` 保存名称与索引，`Images/` 保存原图和缩略图。
- 缓存：`~/Library/Caches/MacTools/`，表情搜索索引和图片在 `MemeSearch/` 子目录。
- 截图：`~/Pictures/MacTools/yyyy-MM-dd/`
- 录像：`~/Movies/MacTools/yyyy-MM-dd/`
- 偏好和短语：`local.wisehan.MacTools` UserDefaults 域。

截图和录屏需在系统设置中允许屏幕录制；麦克风仅在选择开启后申请。文件搜索遇到受保护目录会提示不可访问。当前不会自动粘贴到其他应用，因此无需为自动粘贴申请辅助功能权限。

除表情包联网搜索和图片下载外，其余处理在本机完成。表情搜索仅访问勾选的来源，关键词会发送至所选 API 或网站；ChineseBQB 下载公开目录后在本机匹配名称和分类。memecub 匿名每个 IP 每日 20 次，其他来源遵循各自限制。不上传本机文件或剪贴板记录，不配置付费 API 或遥测。保存的历史不额外加密，使用 macOS 用户目录的访问保护。带保密或临时标记的剪贴板内容自动跳过；来源应用识别基于复制时的前台应用，无法保证识别所有敏感内容，可按需暂停记录。

## 代码结构

`App/` 管理应用、窗口与快捷键；`Core/` 管理设置、文件和模型；`Clipboard/`、`Capture/`、`Recording/`、`Search/`、`Storage/` 放业务控制；`Views/` 放 SwiftUI 界面。主模块使用中文注释，Swift 文件单行不超过 200 字符。

表情包搜索使用 `Memes/MemeSource.swift` 统一适配五个来源，包含 [memecub](https://github.com/liyupi/memecub) 公开 API 和 [ChineseBQB](https://github.com/zhaoolee/ChineseBQB) 公开目录；各来源的开放范围、额度与接入细节见 [第三方说明](THIRD_PARTY_NOTICES.md)。当前没有嵌入第三方 SDK 或源代码。使用 AppKit、SwiftUI、ScreenCaptureKit、Vision、AVFoundation、CryptoKit 等 Apple 系统框架。以后需要第三方依赖时，仅使用免费开源方案并保留对应许可证。

### 建议阅读顺序

1. `App/MacToolsApp.swift` → `App/WindowCoordinator.swift`：了解菜单栏应用的启动、功能路由和窗口生命周期。
2. `App/HotKeyManager.swift`：了解跨应用快捷键、应用内按键和快捷键录入之间的配合。
3. `Clipboard/ClipboardStore.swift` → `Core/LocalFiles.swift` 中的 `ClipboardPolicy`：了解内容收录、去重、收藏与自然日清理。
4. `Capture/CapturePresentation.swift` → `RegionSelector.swift` → `CaptureService.swift` → `CaptureController.swift`：了解窗口收起、悬停建议、选区坐标、像素倍率和采集会话。
5. `Capture/ImageStitcher.swift` → `AnnotationDocument.swift` → `AnnotationCanvas.swift`：了解长图匹配、标注数据、预览与导出。
6. `Recording/RecordingController.swift` → `VideoEditorController.swift` → `VideoRenderService.swift`：了解录制边框、预览、裁剪时间轴、逐帧标注与异步导出。
7. `Search/FileSearchController.swift`、`Storage/MediaLibrary.swift`：了解查询取消与文件管理边界。

关键类型与算法已增加中文文档注释，重点说明坐标单位、主线程约束、异步取消、资源释放和规则边界。修改拼接阈值或清理规则时，应同步检查 `Core/SelfTests.swift` 的对应回归用例。

## 依赖管理选择

当前继续使用原生 Xcode 工程，不新增 Podfile。未来出现实际第三方需求时，优先使用 Xcode 集成的 Swift Package Manager（SPM）。

| 能力 | 当前选择 | 引入第三方的条件 |
| --- | --- | --- |
| 页面与布局 | SwiftUI 的 Stack、frame、padding 等布局能力 | 特殊布局先评估系统 `Layout` 能力 |
| 原生窗口与画布 | AppKit / Core Graphics | 若以后增加大量 AppKit Auto Layout 布局，可评估 SnapKit |
| 截图、录屏、OCR | ScreenCaptureKit、AVFoundation、Vision | 系统能力无法满足具体需求时，再评估对应免费开源实现 |
| 包管理 | 当前无外部包；后续优先 SPM | 必要依赖无法通过 SPM 或合理的源码集成使用时，再评估 CocoaPods |

SwiftUI 是 Apple 提供的系统框架，直接 `import SwiftUI`，无需通过 CocoaPods 或 SPM 安装。SnapKit 用于简化 Auto Layout 约束，不替代 SwiftUI 的布局系统；当前选区和标注画布主要依赖精确坐标计算，加入约束库不能直接简化这些算法。

需要新增 SPM 包时，在 Xcode 的 `File > Add Package Dependencies` 中添加仓库并选择所需产品即可，无需把整个应用改成 `Package.swift` 工程。正式引入后应记录实际用途、许可证和版本约束，并将生成的 `Package.resolved` 纳入版本管理，以保留可复现的解析版本。当前未添加任何外部包，也不创建空的依赖配置文件。
